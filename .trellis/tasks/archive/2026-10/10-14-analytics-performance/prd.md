# 扫描性能、诊断与请求界面

## 目标与状态
解决慢加载、剩余原值单位、告警刷屏和请求详情布局问题；统计准确性仍优先。状态：in_progress。用户于最终方案后回复“开始吧”，已批准父项及三个子项实现；现有发布产物仍为 v0.2.5，新版本需完成集成验收后交付。

## 已确认的依据
- 性能：冷扫描约 8.2 秒，未变更缓存扫描 36–43 毫秒；时间筛选 1.4–2.3 秒。单次计算筛选边界的临时实验为 5–17 毫秒；原生日期解析实验冷扫描约 3.7 秒。Sources/Core/Models.swift:169、240；Sources/App/RequestsContent.swift:20；Sources/Core/CodexLogScanner.swift:162、178。
- 单位：菜单页脚、指标副标题、会话标题和列表总计仍有精确数字。Sources/App/MenuPanelView.swift:61；Components.swift:108；SessionsContent.swift:164；RequestsContent.swift:109。
- 诊断：history_base 被无条件告警，稳定 Session ID 被用于选择最长物理文件。Sources/Core/CodexLogScanner.swift:66–76、242。同一次元数据核对发现 264 个独立原生请求被选择策略遗漏，对应 33,666,740 Tokens；这是观测证据，不能当作通用合并规则。
- 性能字段：原生 token_usage_record 无单次请求耗时；task_complete 有完整 Turn 耗时及首次 Token 时间。助手 item 区间估算出现 531,000 tok/s 等失真结果，不能用于填充请求速度。Sources/Core/Models.swift:112–129；请求详情现为 sheet：RequestsContent.swift:121。
- 详细实验、隐私范围及固定上游版本见 research/scan-and-diagnostics.md 和 research/request-timing.md；实时日志增长，实验数字不能作为固定发布验收数据。

## 范围边界
参考 CC Switch 的紧凑表格与右侧详情；保留今天/7 天/30 天/全部、默认 30 秒及离线只读。历史消费统计不变成当前对话内容投影；不增加 API 价格、账号、额度、多 Provider、在线调用、自定义日期、Git 初始化或无关 bootstrap。磁盘持久缓存与字节级增量暂不引入，先验收测量所支持的简单优化。

## 已批准的关键决定与风险
推荐按本地可核验的历史消耗统计，恢复确定存在的原生请求，而非只保留最长文件；总量可能因此合理增加。旧日志缺少独立身份时继续披露计量不完整。性能采用真实 Turn 指标，单请求缺失保持未知。日期解析浮点差异约 1.2e-7 秒，必须覆盖排序、去重及本地日期/小时。以上口径已随最终方案获批；批准记录见 approval.md。
