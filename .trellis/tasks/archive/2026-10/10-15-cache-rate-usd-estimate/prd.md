# 缓存率与美元用量估算

状态：已实现并验证 v0.2.16/build18；用户授权主Agent自行复核后执行，复核、分阶段实现及独立检查完成。任务开始基线为v0.2.15/build17。

## 目标与用户决定

让用户看清本机已计入用量的缓存输入比例与美元参考价值，保持原生、只读、完全离线和清爽的 A 分组布局。

2026-10-15 用户明确答复“符合的”：美元金额按官方 API 标准参考价折算，用于了解用量价值，不解释为订阅实际扣费或余额。

## 任务开始时的现状与依据

- 用户要求新增缓存率及美元消耗展示；未要求联网、余额或订阅账单。
- 现有 R01/R05/R06/R07/R09 提供菜单、总览、模型、会话和请求详情；R08 请求列表已无横向滚动，不能因新字段破坏。
- TokenUsage.input 包含 cachedInput，output 包含 reasoning；cachedInputKnown 合并时用逻辑与。依据 Sources/Core/Models.swift:4-33、55-70。
- 当前 CLI 输出 total/models/sessions/records，未有派生百分比和金额。依据 Sources/Report/main.swift:5-25。
- Scanner 当前按模型/事件时间归属，不保留服务档位、上下文计费档或缓存写入计费字段。依据 Sources/Core/CodexLogScanner.swift:437-482、951-968。
- 当前需求已允许未来 API 等值估算，但禁止猜价、伪造已知与订阅实际扣费；当前实现没有此功能。
- 官方网页本轮核验区分 input/cached input/output，并有多档服务、长短上下文、缓存写入及附加费。研究记录见 research/pricing.md；原型与正式定价表必须区分。


## 已批准并实现的范围

- R18：显示“缓存率”，同范围先汇总缓存输入和输入再相除；一位小数。零输入为 —（无输入），缺失缓存拆分为未完整记录，真实零缓存为0.0%。
- R19：显示“API 等值估算”，USD；按版本化、已核验的官方 Standard 短上下文三项参考价折算非缓存输入、缓存输入及输出。所有历史统一使用随 App 内置的当前快照，不声称恢复当时账单；明确不含缓存写入单列费用、长上下文/加速/地域等附加项。
- R01/R05：菜单总量卡下增加紧凑估算行；缓存小卡补缓存率；总览在既有总量/缓存卡补充相应指标，不增加一排大卡片。
- R06：保留 A 模型分组，名称/总量仍是主层级；总量下增加估算，缓存明细区增加缓存率。
- R07/R09：会话详情及会话内模型、已计入请求详情按同口径展示；原始累计快照/last_usage不估价，避免被误当额外消耗。
- R08：请求表不新增列、不恢复横向滚动；无金额排序、趋势、预算或新筛选。
- CLI：同范围与同价格快照的数值、状态和覆盖量可核对；继续使用同一 Core 计算。
- R17：先完成并验证缓存率，再实施金额；完成后交付独立 App 和完整源码包，不安装、退出或替换用户 App，不提交推送。

## 统计约束

- T12：缓存率来自已去重接受用量，不平均组百分比；未知和零不同。
- T13：金额为派生估算；推理已包含在输出，不重复计价。只精确匹配有确认价格的模型，不猜测内部标识/别名，不把未知当0。
- 费用按已接受记录分别计算后汇总；未知模型、缺价或必要缓存拆分缺失的记录进入未覆盖量。可估部分不因其他记录未知而丢弃；缺失原因可查。零输入不要求缓存拆分，零用量可以确认金额0。
- 部分覆盖必须标“已估算小计”并显示未估算 Token；全无覆盖显示无法估算。覆盖不是准确度，不能让用户误以为是订阅消费比例。
- T01–T11 保持不变；Scanner 的去重、归属、模型识别不变。

## 验收标准

1. I=1000/C=800得80.0%；I=100/C=100和I=900/C=0合并得10.0%（不是50%）；真实0%、零输入、未知可辨。
2. 合成每百万价 input=2/cache=0.1/output=10，I=1000/C=800/O=100得0.00148 USD；Reasoning变化但Output不变时金额不变。
3. 覆盖完整、部分与完全未知模型；缺缓存字段但有非零输入、只有输出、真实零用量分别符合契约；部分合计不漏掉可估记录。
4. 先以Decimal计算再显示；微小非零不显示$0.00。多个模型/会话/记录合计一致；日期切换和重复/归档/压缩仍只估算已计入部分。
5. 相同范围、now和价格版本下，App各页面与CLI金额、缓存率、覆盖量及状态一致。切配色不扫描、不丢搜索/选择；失败刷新保留旧成功统计。
6. 菜单288pt；分析950/1120宽、两配色深浅色、常显滚动条、长名/大数/未知文案无横滚；模型主次关系不被新指标挤乱。
7. 正式构建与签名核验、合成Core/格式/Store/原生渲染检查；实际VoiceOver和鼠标悬停如未执行仍列待验收。

## 范围外及取舍

不做订阅账单/余额、账户/API Key、运行时联网查价、汇率、预算、多Provider、用户价格编辑器或自动价格更新。使用统一参考快照使历史可比较，代价是不复原历史价格和完整计费项；更新App价目表可能重算同一日志的等值估算，价表版本可查。
