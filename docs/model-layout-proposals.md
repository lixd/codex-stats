# 模型统计页布局提案

2026-10-15历史提案；A分组列表曾于v0.2.15/build17实现，独立页面已于2026-10-16的v0.2.19按[R22](remove-model-statistics-design.md)删除。本文及HTML仅保留设计历史，不是当前重建目标。原八列 Table 是 v0.2.14 历史；下述 HTML 是选择方向时的预览，原生验证单独记录。

## 问题与依据

用户提供的模型页截图显示：每个模型被压成一个紧密的横排，八列相近的数字没有明显阅读顺序；页面上方标题、说明和独立排序行占用较多空间。当前代码 `Sources/App/DashboardView.swift:347` 的 ModelsContent 确认了该结构：六项 Token 数字各76pt、会话44pt、模型150pt；数字12pt，只有总计稍加强调。

因此不继续缩小字体或压缩列宽。保留纵向滚动，用每个模型内部的分组建立层级，避免横向滚动；沿用 D 的浅青页面、白色内容面与现有颜色角色。

## 三个可比较的结构

[打开预览](http://127.0.0.1:8754/?variant=A)，或运行 `python3 -m http.server 8754 --bind 127.0.0.1 --directory docs/prototypes/model-layout`。预览路径：[独立 HTML](prototypes/model-layout/index.html)。这是设计用原型，不属于 App 运行时；不读取日志、不保存偏好、不请求外部资源。顶部刷新、时间范围及风险提示仅为外壳示意。

| 方案 | 结构 | 收益 | 取舍 |
|---|---|---|---|
| A 分组列表（推荐） | 一模型一组；名称/会话在左，总量在右；下层输入与输出两组，缓存/非缓存/推理从属显示 | 完整明细可直接阅读，跨模型上下比较，无需新增点击或展开 | 每组约150pt，比当前表格需要更多纵向空间 |
| B 双列卡片 | 每模型独立卡片；总量更大，输入输出纵向分区 | 少量模型更轻松，重点突出 | 跨卡片对照需要左右扫视；不能承诺所有模型一屏显示 |
| C 列表与详情 | 左侧模型/总量/会话，右侧一个模型的完整明细 | 模型多时便于定位，单模型阅读从容 | 比较需要切换；引入选择及筛选后的选择规则，复杂度更高 |

三种方向不是未来的三个可切换主题；只选择一个生产布局，现有浅青/晴蓝仍仅切换颜色。

## 已批准 A 的布局契约

用户于2026-10-15回复“A 吧”，批准按 A 实现，原生验证已完成。关联 R04/R06/R12/R17，保持 T01/T02/T06/T07。

- 保留共享页头、四档时间范围与显式风险提示。仅把模型内容标题收为15pt“模型用量 + 模型数”，搜索和排序并在同一行；不改其他页面。
- 页面内容左右24pt。每组白底、10pt圆角、细边框；组间12pt，组内约18–20pt。名称14pt/semibold，总量21pt/semibold。输入/输出值14pt，中性正文色；次要标签与会话约10–11pt。原生实现应以可读性为准校准，不要求机械复制浏览器字形。
- 名称与总量首行分两端；输入/输出第二层并列，以轻分隔线区分。缓存和非缓存放在输入下，推理放在输出下。无需按模型配彩色背景、增加仪表盘或添加缓存率。
- 950pt 与1120pt窗口宽度均不横滚，不以裁切或隐藏滚动条掩盖溢出。长名称可换行，完整值可查；空间不足时从属明细换行。纵向滚动是预期行为，不追求所有模型一屏。
- 保留现有六种排序及不区分大小写搜索；无模型/无匹配有明确提示。刷新失败继续保留成功数据和错误说明。模型数量只描述当前筛选结果，不作为请求数。
- Total=Input+Output；缓存属于输入，推理属于输出。缺失缓存时缓存与非缓存都保持“未完整记录”。未知推理不显示0；Unknown model 不猜归属。真实零与未知不同。
- 本轮合成数据整数自洽，与截图的舍入显示有少量差别，不是对真实统计的修正。Unknown model 的缺字段仅用于边界展示，不意味着未知模型必然缺缓存。

## A 原生实现与验收契约（已实现）

- ModelsContent 继续从共享 UsageStore 取得当前 period 的 summary.models。保持现有名称匹配及六项排序、降序同值名称升序；标题显示当前匹配模型数和范围。范围、刷新、错误由现有共享头部/Store负责；本页不新增数据副本、定时器或扫描。
- 替换模型页原生八列 Table 为 SwiftUI `ScrollView(.vertical)` + `LazyVStack`，组间12pt。每模型稳定身份使用已有 ModelUsage.id，不新增选择/展开/主题布局状态；无表格行选择的旧功能需要保留。请求页 Table 不变。
- 页面左右24/上下20pt；工具行标题15pt、模型数11pt；搜索170pt、原生排序Picker整体170pt（含标签）。工具区允许根据可用宽度把搜索排序换到下一行，不缩小正文字体。内容组 padding18pt，10pt圆角和现有card/stroke角色。
- 首行模型名14pt semibold、可换行，完整名称help/AX；会话数11pt secondary。右侧总量21pt semibold（等宽数字）+“总 Token”11pt标签。下层顶部15pt间距/细分隔：输入、输出双区，各自14pt主值、11pt标签与从属数据；两区间距24pt和轻分隔。未知长文或长模型可增高卡片，禁止固定卡片高度、截断完整未知状态或以裁切隐藏溢出。
- 输入从属缓存和非缓存，输出从属推理；保留完整中文语义的可访问标签及精确数值/未知 accessibilityValue、help。使用现有 abbreviated/detailedNumber；不增加B单位或自算缓存率。
- 不增加可点击模型或键盘选择行为。搜索和原生Picker保持Tab聚焦与系统键盘行为；原生纵滚支持滚轮/触控板及系统辅助功能。所有数字可由辅助功能读取精确值，不仅仅读紧凑数字；人工VoiceOver另验。
- 无模型/无匹配沿用明确空状态；未知模型解释日志未记录归属。0仍为真实0，缓存/推理unknown使用对应known标志，缓存unknown时非缓存也unknown。
- 验证原生真实视图950×630和1120×760，两配色×深浅色、常显纵滚条、80个合成模型的最后一项可达；测量NSScrollView document/clip宽证明没有横向溢出。LazyVStack只要求真实数据80条和可达最后项，不把已实例化子视图数误当模型数量。
- 额外检查长模型名、大Token数、未知字段和真实零，空结果及恢复、实际搜索binding、切配色后查询/摘要身份/成功刷新时间保持。原生Picker非默认项与VoiceOver若没有真实执行，明确留人工验证，不用静态截图代替。
- 本次交付源码v0.2.15/build17，原生验证通过后已推进基线；独立/tmp构建及源码包，不安装/启动/替换/退出用户App，不提交推送。

### 常显滚动条验证方法补充（实现前记录）

SwiftUI 根据进程启动时的NSScroller.preferredScrollerStyle布置滚动内容；测试在挂载后直接强改NSScrollView.scrollerStyle不等同于系统初始样式。测试宿主需用启动参数 `-AppleShowScrollBars Always` 创建独立的原生预览进程，并断言preferred为legacy，再验证950/1120宽度及80条末项。Scripts/render-ui-previews.sh只追加此受控子进程，不写全局/用户偏好、不影响App。普通预览保持现有样式；测试两者分别留证。禁止用隐藏横向条、硬扣17pt或放宽几何断言掩盖溢出。
