# 请求日志紧凑布局

2026-10-15。状态：**已实现并完成本轮原生验证，v0.2.14/build16**。R04/R08/R09/R12/R17，T01–T11保持。任务：[10-15-compact-request-layout](../.trellis/tasks/archive/2026-10/10-15-compact-request-layout/prd.md)。

## 问题与用户收益
请求页顶部两行头部、较大页面留白和十列的原生单元格空间叠加，减少可见行且末列需横滚。收紧非数据空间，默认窗口优先同屏看十列；大量记录继续原生纵向滚动。

## 当前布局与交互
- 只调整请求页；D布局、浅青/晴蓝颜色和其他页不变。
- 页头一行：页面标题、真实刷新时间、立即刷新及刷新间隔；隐藏本页重复的来源副标，头部上下12/左右16。四档PeriodPicker移到页内记录数右侧，仍共享Store范围，不新增局部范围。
- 页面左右16/上下12，纵间距8，筛选行间距8。记录数仍16、数据正文仍12、辅助10–11；不靠小字塞内容。
- 表格十字段不删。按本轮真实NSView宽度测量收紧时间、数字和类型列，项目/模型自适应；模型/项目单行并保留完整help，未知字段仍明确显示。默认1120×760以及最小950×630均不得横滚。不遮列或隐藏滚动条假装适配。实际表格可用宽>=900pt使用十列；不足900pt使用七列：模型+类型、非缓存输入+缓存、耗时+速度各合成一列两行（明确标签/单位），保留全部十项字段，数字仍12pt。宽度预算须预留原生常显纵向滚动条占用，不只按overlay滚动条验证。完整模型/项目help保留。
- 请求详情从360pt右侧栏改为原生sheet（420×600pt，适配最小630pt内容高度）；复用同一个RequestDetailView、关闭/Esc和完整字段，不挤压列表。统一sheet比额外维护侧栏/浮层两种详情状态更简单；此项更新R09原侧栏契约。关闭后搜索/筛选/排序保留，沿用原关闭详情清空selection的行为；不引入重复详情状态。
- native Table仍管理纵向滚动和选择，宽度自适应后文档宽不得超过clip宽。搜索/模型/排序/范围/明细/关闭、完整身份/Token/估算说明及诊断入口保留；不改变计量、扫描或生命周期。

## 验证
本轮旧版原生测量1120：clip887/doc962，950：clip717/doc962；原生列间距17pt不能忽略。先测旧版与新版表格的top/height、document/clip宽和实际列数；合成多条记录检查可见行及最后一行到达。两色×深浅色、1120/950、详情/空/未知/长名称/大数，真实原生截图与几何断言；Core及编译、必要共享格式检查。鼠标滚动、触控板手感及VoiceOver需人工，原生预览不作为这些操作已验收的证据。独立临时App，不安装/退出/替换用户App、不提交推送。
