## 决策与阶段

D 为唯一布局；浅青为默认，晴蓝（原型 A）仅切换颜色，不切换布局。外观始终跟随系统明暗，不新增明暗选择、自动日程、B/C、主题编辑器或网络依赖。用户明确要求先做好一套再动手另一套。

1. **阶段 D**：只实现 D 布局和固定浅青角色；完成原生构建、合成深浅色/小窗口/状态预览和必要回归，记录 D 验收结果。此阶段不增加晴蓝代码、选择器或偏好。
2. **阶段 A**：D 验收通过后，增加晴蓝和设置中的“配色”选择；复用相同视图树。核验持久化、同时更新菜单/分析/详情、切换不丢状态及不触发扫描。最后发布源码版本 v0.2.13/build15 的独立构建，不安装或启动用户 App。

原型 HTML 不会进入 App。采用系统 SwiftUI/AppKit/Charts，保留原生 Table、Picker、搜索、复制和键盘行为。旧 Sage + Teal 不作为第三套主题保留。

## 阶段 A 的偏好与更新契约

- 设置增加一个原生 Picker“配色”，选项“浅青”“晴蓝”，默认浅青；说明“只改变配色，外观跟随系统”。保存键 `CodexStatsColorPalette`，原始值 cyan/blue；未保存或未知值显示默认浅青。不增加迁移兼容层。
- `Sources/App/Appearance.swift` 保存固定两套配色、环境键和环境解析角色；独立 Store/格式测试脚本显式编译该文件，不把 UI 偏好放进 Core。
- `UsageStore` 仅新增可观察的配色偏好与原有注入 UserDefaults 的读写；切换不调configureTimer/refresh/updateRoot，不清报告、不清summary缓存、不改路径/范围。用户有意的偏好恢复默认属于配置契约，不能吞掉统计错误。
- 通过 SwiftUI environment 传递选项；CPTheme颜色角色由环境解析，可用macOS14的ShapeStyle.resolve(in:)。不新增全局可变主题单例、不在颜色provider读取UserDefaults、不为切换使用.id重建整个视图树。固定两套角色，不做通用主题引擎。
- 菜单和Dashboard根节点从同一Store注入环境；sheet/独立详情和预览宿主同样接收当前选项。图表、背景、边框等同一角色一起更新。静态角色不能在第一次读取时把当时颜色永久缓存。
- 搜索/排序/详情选择、设置中尚未应用的路径文本、时间范围、已打开页面在配色切换时保留。明暗始终由系统环境决定。
