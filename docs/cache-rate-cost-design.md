# 缓存率与美元估算：当前实现设计

2026-10-15。**已实现 v0.2.16/build18。** 用户授权自行复核后实施；先缓存率、后美元估算，两阶段验证完成。
关联 R18/R19、T12/T13及 R01/R05–R09/R12/R17；[任务](../.trellis/tasks/archive/2026-10/10-15-cache-rate-usd-estimate/prd.md)。本次实测与人工验收边界见[验证记录](../VERIFICATION.md)。

## 1. 当前与目标

此前v0.2.15只有Token；当前保留模型A分组、D布局和双配色，补充缓存输入比例和“API等值估算”，帮助理解用量价值。2026-10-15用户已接受按官方API标准参考价折算；不接入账户或账单。

## 2. 缓存率

同范围先合计再算 `sum(cachedInput) / sum(input)`，不平均百分比。展示百分比一位小数；help和无障碍包含精确分子分母。input=0显示“—”并解释无输入；input>0且cachedInputKnown=false显示“未完整记录”；仅已知cache=0显示0.0%。无成功报告沿用现有加载/失败态，不填0。跨范围、模型、会话与请求使用相同规则。

## 3. 价格与含义

内置版本化美元价表（核验日期、官方URL、模型精确ID、Standard短上下文的输入/缓存输入/输出每百万价格）；运行时不联网、不读凭证或模型配置。初始价表限本轮已确认的 gpt-6.1-sol/gpt-6-astra/gpt-6-luna/gpt-5.3-codex，具体数值见任务研究；其他模型不猜价。新增模型或改价必须有来源/日期、测试和新价表版本，随App交付。

所有日期统一按该快照折算，表示可比较的参考价值，不恢复历史实际账单。三项公式：

`USD = ((input - cachedInput) * inputPrice + cachedInput * cachePrice + output * outputPrice) / 1_000_000`

输出包含推理，不再加推理费。参考基准不估缓存写入单列费用、长上下文加价、Fast/Ultrafast、Batch/Flex优惠、地域/税费、工具调用或订阅折算。此处的“完整”仅指此三项参考指标的数据覆盖，不声称完整官方账单。[官方定价](https://developers.openai.com/api/docs/pricing)有这些不同计费维度，当前日志统计未保留全部依据。

价格说明：设置页以只读区显示价表版本、核验日期、计价基准及不含项；金额help/AX包含同样关键信息。没有打开网页或价格编辑器的新交互。

## 4. 未知、精度和覆盖

按接受记录估算后合计。模型无价或input>0且缓存拆分未知时该记录不估价；output-only不依赖缓存拆分，零用量确认0。保留已估金额、已覆盖/未覆盖Token、原因汇总及价格版本，不保留新的记录副本。未知记录不导致其他已知记录金额丢失。

状态：无成功报告沿用加载/错误；成功零用量显示$0.00；非零用量全部可估为“API等值估算 ≈ $…”；部分可估为“已估算小计 ≈ $…”并同时显示“另有…Token未估算”；全部未知为“无法估算”，具体原因可查。部分/未知不得仅靠悬停区分；无覆盖分母时不制造覆盖百分比。

货币标USD，固定$与小数点/千位逗号便于比较。通常保留两位小数；0<金额<0.01时显示“< $0.01”。采用Foundation Decimal（从整数字符串/十进制价格构造，不经Double算钱），汇总之前不舍入；详情help显示至少8位小数并按需要保留精确值。Decimal计算错误显式暴露为无法计算，不退回0；CLI输出精确十进制字符串、USD、状态、覆盖量和价表版本。缓存率的无值同样带状态，不能只输出null。

## 5. 数据流与刷新

不改Scanner解析、计量、历史所有权或去重。在Core新增小型纯派生模块，接受已计入记录序列和内置价表，累加总额及按模型/会话分组的标量结果。使用既有本地日bounds和同一个now；请求详情只对record.usage估算，原始snapshot/last_usage不估价。

后台ScanWorker在扫描成功后遍历sessions[].records一次，构建按会话/日期/模型的标量估值索引，和report成对发布；不创建全量records数组。UsageSummary当前范围缓存建立时只合并索引桶；key沿用报告修订/范围/本地日期/时区，编译期价表版本由索引固定，不另设运行状态。失败刷新保留旧报告及其索引；切路径同时清空；旧路径的扫描及索引不覆盖新路径。会话列表排序不计算金额；详情从当前范围摘要读会话/模型结果。金额不参与原Token相等性或重算扫描；不增加Timer/Task/持久缓存。Report CLI复用同Core入口，同all范围与固定now应与App一致。

缓存率直接基于对应TokenUsage；金额逐记录处理，不能仅在已经合并且cachedInputKnown=false的模型总量上整组排除。UI不自行匹配价格或解码日志。

## 6. UI布局契约

| 位置 | 新增展示 | 密度与语义 |
|---|---|---|
| 288pt B菜单 | 总量卡下金额；缓存输入小卡底部缓存率 | 金额11pt、缓存率10pt；先保留Token主数；部分覆盖自然换行，不截断限定词 |
| 总览 | 总Token卡副区加金额；缓存输入卡补缓存率 | 不新增一排大卡；旧包含关系文案仍可读，副行10–11pt |
| 模型A分组 | 右上总量标签下加金额；输入子区补缓存率 | Token21pt保持，金额12pt medium、比例11pt；长金额/未知原因换行，必要时金额放卡片独立下行 |
| 会话详情/会话内模型 | 已计入用量区下放金额及缓存率 | 不改左侧会话列表宽度或选中方式；12pt次级明细 |
| 已计入请求详情 | TokenDetails后加派生摘要 | 原始快照与last_usage不估价；说明累计记录不等于单次请求账单 |
| 请求表/趋势/排行 | 不新增字段 | 保留无横滚、现有Token排序和筛选 |

金额/缓存率无新警告Banner；沿用主题动态颜色，限定词和未知状态使用文字而不只靠颜色。所有新增字段提供完整AX名称/值/包含关系；长名、大数和部分覆盖允许垂直扩展，不压成难读小字。

## 7. 验证与交付

先缓存率实现+检查，再金额。Core用独立手算表验证加权、未知、分子分母、模型切换/重复/归档/压缩仅计已接受部分、Decimal及各层求和；格式三区域设置。Store检查范围缓存与失败保留；原生渲染检查288菜单、950/1120、两配色深浅色、overlay/legacy及部分覆盖/长名/大数。受控规模检查保证无每次body重扫记录或排序比较器估算。

运行 test.sh、test-token-display.sh、test-usage-store.sh、render-ui-previews.sh 和优化构建/签名核验。新增指标测试要验证真实Core/格式器，不复制实现作为预期值。实际鼠标/VoiceOver等未执行则保持待验收。交付独立/tmp App与源码包，更新文档/验证记录与Trellis；不操作用户App、不提交推送。

## 8. 取舍

不增加账单/预算/价格同步或任意配置层。固定参考价可保持离线、明确与可复核；代价是不能复原真实完整扣费。未有价格的内部模型保留未知，比猜价更符合准确性优先。后续如果用户要求长上下文/服务档估算，需要单独设计数据来源与接受边界。
